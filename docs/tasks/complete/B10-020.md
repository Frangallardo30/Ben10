# Ajustar aura y anular historial por administración

## Estado

Hecha

## Pedido

Después del panel de B10-017, permitir exclusivamente a administradores sumar o restar puntos sin votación y retirar propuestas del historial visible, una o varias a la vez. Caso concreto: se aprobó una resta de prueba a un amigo y se quiere deshacerla y quitar del historial esa propuesta.

## Criterios de aceptación

- [x] Solo Administrador, con motivo y confirmación explícita, puede ejecutar cada acción.
- [x] Un ajuste forzado permite sumar o restar puntos y queda auditado e identificado como administrativo.
- [x] Se puede elegir una propuesta por ID, la última de una persona o varias propuestas concretas; una vista previa confirma exactamente las afectadas.
- [x] Anular una aprobada revierte su efecto original: si restó puntos, los devuelve; si sumó puntos, los retira. Desaparece del historial visible según la selección confirmada.
- [x] El cambio se refleja de forma coherente en perfil, ranking, estadísticas, historial y mensaje de Discord; no se oculta una fila dejando su efecto de aura aplicado.
- [x] Operaciones repetidas o concurrentes no vuelven a ajustar el aura ni anulan registros distintos de los confirmados.
- [x] Se conserva una auditoría privada con actor, fecha, motivo, selección y efecto; se define la retención de datos y qué se oculta, sin confundirlo con borrado físico irreversible.

## Implementación

Se incorporaron `/moderar ajustar`, `anular`, `anular_varias`, `anular_ultima`, `confirmar` y `operacion`. Las vistas privadas duran diez minutos, fijan los IDs y efectos y solo las confirma su creador con Administrador actual, en el mismo servidor. Se admiten ajustes enteros ±1000000 excepto cero, motivos de 3–250 caracteres y hasta diez IDs por selección.

Las tablas nuevas se preparan en la migración del Worker sin borrar datos. Un lote atómico reclama la operación, valida las filas congeladas, aplica el ajuste o cambia el estado a `voided`, guarda auditoría y encola actualizaciones. Confirmaciones repetidas o superpuestas no duplican el efecto. Un fallo revierte todo el lote.

Anular retira el efecto original sin compensaciones adicionales. Todas las consultas públicas excluyen anuladas; se conservan propuestas, votos y auditoría privada indefinidamente. Los ajustes son identificables públicamente con motivo genérico, sin publicar el motivo privado ni avisos automáticos. El sincronizador neutraliza el mensaje original y el aviso de cierre conocido, incluso cuando ese aviso termina de enviarse después de la anulación. El cron reintenta también si solo se conoce el ID del aviso. Los avisos pendientes se cancelan.

Comportamiento y límites documentados en [la especificación](../../specs/aura.md) y [la guía del panel](../../operations/moderation.md).

## Límites y entrega

Implementación y validación locales completas. El usuario autorizó publicar en `main` para activar el despliegue conectado de Cloudflare; el resultado remoto de Cloudflare debe verificarse por separado. Las pruebas de runtime necesitaron apertura de puertos localhost fuera del sandbox. No se enviaron mensajes reales a Discord. La confirmación de producción sigue en B10-006. La neutralización visual requiere permisos y entrega de Discord; mensajes sin ID, copias y avisos de entrega incierta sin ID requieren revisión manual. No se promete borrado físico ni eliminación de notificaciones previas.
