# Mejorar diagnóstico y operación en Cloudflare

## Estado

Hecha

## Pedido

Facilitar la detección de fallos de D1, registro de comandos y llamadas a Discord sin exponer tokens ni motivos sensibles en registros públicos.

## Criterios de aceptación

- [x] Los errores relevantes tienen códigos o mensajes seguros que permiten distinguir D1, Discord y validación.
- [x] El registro automático de comandos deja un resultado visible para operación sin revelar el Bot Token.
- [x] La comprobación de salud no publica datos innecesarios de configuración.
- [x] La guía explica cómo ver logs de Cloudflare y recuperar el servicio después de rotar el token.

## Implementación

Se centralizó el diagnóstico en `src/diagnostics.js`. Los errores de las llamadas a D1 se convierten en `D1_FAILURE` antes de registrarse; los de Discord distinguen transporte, respuesta inválida y rechazo HTTP. Los eventos JSON usan solo códigos fijos, área y estado HTTP opcional. Se eliminaron errores crudos, nombres de excepciones, IDs y cuerpos de respuesta de los logs del Worker. El registro de comandos informa `COMMANDS_REGISTERED`, `COMMANDS_CURRENT` o `COMMANDS_TOKEN_MISSING`, y clasifica sus fallos.

`/health` pasa a ser una comprobación pública de liveness: HTTP 200 con `{"status":"ok"}`, sin consultas D1 ni datos de configuración. Las comprobaciones de dependencias se realizan mediante logs autenticados y las pruebas de B10-006. Se revisó `wrangler.toml`: logs de aplicación activados e invocaciones automáticas desactivadas.

La [guía de operación](../../operations/cloudflare.md) explica cómo consultar logs, interpretar los códigos y recuperar el servicio después de rotar el token. También se actualizaron la spec, QUALITY.md y las instrucciones de arranque guardadas del entorno para el nuevo contrato de `/health`. No se cambió el permiso de red pendiente de B10-006.
