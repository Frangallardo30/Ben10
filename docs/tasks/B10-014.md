# Consultar historial de votaciones

## Estado

En curso

## Pedido

Permitir consultar propuestas rechazadas y abiertas además de los cambios aprobados del historial actual.

## Criterios de aceptación

- [x] Se pueden distinguir propuestas aprobadas, rechazadas, abiertas y vencidas.
- [x] La consulta está paginada, separada por servidor y no altera el aura.
- [x] Se define si incluye propuestas creadas por la persona o dirigidas a ella.

## Implementación

Se añadió `/votaciones [usuario] [pagina]`, separado de `/historial` que conserva solo los cambios aprobados. Consulta propuestas dirigidas a la persona (por defecto, quien ejecuta el comando), no propuestas creadas por ella para terceros. Se separan por servidor y ordenan por fecha de creación e ID descendentes, ocho por página.

Se muestran los cinco estados, puntos propuestos, motivo (máximo 250 caracteres), fecha y proponente. Una abierta cuyo plazo pasó se presenta como vencida mediante CASE en la consulta, sin alterar su estado en D1. Hay mensajes para listas vacías y páginas inexistentes; las páginas deben ser enteras entre 1 y 1000000. Se desactivan las notificaciones por mención.

Se añadieron el comando a `/info`, README y spec y la versión de registro v7 para publicar el nuevo comando. La consulta usa las fechas heredadas sin requerir una migración ni modificar el esquema.
