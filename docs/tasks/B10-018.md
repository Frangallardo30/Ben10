# Recuperar el comando /info en Discord

## Estado

En curso

## Pedido

El usuario no ve `/info` ni `/historial` en su servidor, aunque sí ve `/aura` y `/perfil`. Diagnosticar el registro y hacer que el Worker repare comandos globales ausentes.

## Criterios de aceptación

- [x] El Worker intenta registrar de nuevo los comandos tras este cambio.
- [x] Cada revisión programada compara la lista real de Discord y vuelve a registrar si falta `/info` u otro comando esperado.
- [x] La falta del token o un error de la API queda visible en los registros, sin imprimir el token.
- [ ] `/info` y `/historial` aparecen y responden en el servidor del usuario.

## Implementación

Se incrementó la versión de registro a `v4`. Después, el cron comprueba los comandos globales en Discord cada cinco minutos y ejecuta el registro completo cuando falta uno o cambia su descripción. Se añadió un aviso claro si falta `DISCORD_BOT_TOKEN`.

Una captura posterior mostró que Discord seguía ofreciendo solo `/aura` y `/perfil`, aunque Cloudflare indicaba una implementación de `main` lista desde hacía 14 segundos. Se añadió la comprobación de registro también al usar cualquier comando existente, para no depender exclusivamente del cron. La comprobación corre en segundo plano después de responder a la interacción.

Diagnóstico del 2 de noviembre de 2026: el usuario consultó `/health` en el Worker de producción y obtuvo `bot_token_present: false`, mientras la clave pública, el ID de aplicación y D1 estaban listos. El registro queda bloqueado hasta restaurar `DISCORD_BOT_TOKEN` como secreto del Worker `ben10` en producción. No guardar ni compartir su valor en este repositorio.
