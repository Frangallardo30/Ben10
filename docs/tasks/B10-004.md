# Permitir cancelar una propuesta abierta

## Estado

En curso

## Pedido

Permitir que quien creó una propuesta la retire antes de que termine la votación, sin alterar el aura. La caducidad automática se trata en B10-009.

## Criterios de aceptación

- [x] Solo quien creó la propuesta puede cancelar la suya mientras esté abierta.
- [x] Cancelar no modifica el aura ni borra el historial aprobado.
- [x] El embed muestra que la propuesta fue cancelada y desactiva los botones.
- [x] La cancelación repetida o concurrente no cambia dos veces el estado.

## Implementación

Se añadió el botón explícito «Cancelar propuesta» y el estado `cancelled`, sin cambiar el esquema de `proposals` (su estado es texto sin restricción). Se validan servidor y creador y se usa una actualización condicional en D1 con estado abierto y vencimiento futuro. El mismo lote marca como vencida una propuesta fuera de plazo y guarda la revisión para sincronizar el mensaje.

La primera transición confirmada gana frente a una carrera con el voto decisivo; los votos existentes y las aprobaciones anteriores se conservan. Cancelar no crea un aviso de cierre de B10-011. El Durable Object publica «Cancelada sin cambiar el aura» y retira todos los botones. El botón reconoce la interacción antes de esperar a D1 y los errores son efímeros.

La preparación marca una sola vez los mensajes abiertos conocidos para sincronizarlos con el nuevo botón, con `cancel_button_v1` en `bot_settings`. Se actualizó `/info`, README y la spec.
