# Avisar al cerrar una votación

## Estado

En curso

## Pedido

Publicar un aviso cuando se aprueba o rechaza una propuesta, indicando la persona afectada y el cambio de aura si corresponde.

## Criterios de aceptación

- [ ] Hay un solo aviso por cierre, con el resultado correcto y sin menciones inesperadas.
- [x] Una propuesta rechazada o vencida no cambia el aura.
- [x] Los fallos de Discord no duplican avisos al reintentar.

## Implementación

Se guarda una fila única en `proposal_notifications` dentro del mismo lote que cierra la propuesta. La tabla se crea automáticamente en D1 y está incluida en `schema.sql`. No se importan cierres antiguos. `waitUntil` entrega el aviso en segundo plano; el cron atiende pendientes. Una reserva condicional persistida antes del POST impide envíos concurrentes o repetidos. El aviso usa el resultado guardado, omite el motivo y desactiva las menciones.

El 429 se reintenta respetando `retry_after`. Otros errores, respuestas perdidas o interrupciones tras reservar el envío quedan en `uncertain` o `sending`, sin reenvío automático. Esto evita duplicados incluso si Discord publicó el mensaje antes del error, pero no garantiza que siempre llegue un aviso. La entrega exactamente una vez queda pendiente para esos casos ambiguos; requieren revisar el canal. No se añaden puntos al entregar un aviso: el aura sigue calculándose exclusivamente de propuestas aprobadas.

Se documentó el permiso Send Messages y se actualizó la invitación. No se cambiaron permisos ni se enviaron mensajes reales a Discord.
