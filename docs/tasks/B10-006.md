# Probar el Worker en su runtime y en Discord

## Estado

En curso

## Pedido

Además de las pruebas de Node.js y SQLite, mantener comprobaciones del comportamiento en el runtime de Cloudflare y una lista de verificación en el servidor de Discord.

## Criterios de aceptación

- [x] Un Worker local responde a un PING firmado y rechaza una firma inválida.
- [x] Una base D1 local ejecuta propuesta, votos y consulta de perfil con los bindings reales.
- [ ] El despliegue de prueba en Cloudflare acepta la URL de interacciones de Discord.
- [ ] Se comprueban en Discord los embeds, permisos del rol y cierre visual de botones.

## Implementación

Se extendió `scripts/check-deferred-runtime.mjs` para comprobar un PING con firma Ed25519 generada para la prueba, un 401 ante firma inválida, creación de propuesta, votos, cierre con cuatro votos del rol y consulta del perfil con 100 puntos. Se ejecuta en workerd con bindings locales reales de D1 y Durable Objects. Las llamadas a Discord están simuladas y no usan credenciales reales.

El workflow `Check Ben10Bot` incluye los tres scripts de runtime además de `npm test` y el empaquetado: interacciones y perfil, ediciones serializadas y migración concurrente de fechas. Los resultados locales no se presentan como ejecuciones remotas de CI ni como pruebas de Discord.

La lista de comprobación real está en [QUALITY.md](../../QUALITY.md). El último cambio de aplicación publicado al iniciar esta tarea es `7969c6f` (B10-005); no se confirmó desde este entorno que su despliegue en Cloudflare terminara.
